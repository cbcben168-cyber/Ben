# ICT Trading Desk v0.4.5｜Futu 历史日K一键更新

## 使用说明

8506 的「设置与审计」（数据与审核）页面显示当前归档版本、截至日期和最近完整纽约交易日。点击「检查并更新历史行情」后，本地独立进程连接 OpenD，重新获取 23 只 ETF 从原起始日到最新完整交易日的 QFQ、NONE 日K和复权事件。页面自动显示进度与结果。没有新交易日时仍重核全段；数据完全相同则提示「历史行情已经是最新，无需更新」。

日K只用于趋势、EMA、ATR及因子分析；不授予1H或实时ICT资格。人工计划与 QFQ 价格尺度未经核实，继续暂停叠加与可执行风险回报计算。无需重启即可读取成功发布的版本。

## 发布与恢复

更新只写 `ICT_FUTU_DAILY_ROOT` 下的捕获暂存及候选库。23 只全部通过现有 `verify_payload` 的来源、完整交易日、OHLCV、QFQ/NONE与复权事件校验后，创建独立数据库，再以 `os.replace` 原子切换 `current.json`。旧库不会被覆盖；指针保留 `previous`，可通过 `FutuVersions.rollback()` 回退。重复内容由供应商 SDK 版本、复权估值日期、全部证券 QFQ/NONE 行与复权事件的内容哈希判定，不生成重复档案。任务锁限制同时只有一个本地更新进程；抓取进程最多运行 600 秒，失败状态写在独立结果文件。

2. 将已验收代码和完整 Futu 基线库部署到正式8506专用目录；保持 `ICT_FUTU_DAILY_ARCHIVE` 指向只读保留的基线库。配置 `ICT_FUTU_DAILY_ROOT` 指向该目录下独立可写版本目录。保留原 `ICT_V04_DB`、`ICT_V04_HISTORY`、`ICT_EXPERIMENT_DB`、Alpaca 与 v0.4.3 档案路径。
3. 在隔离端口和正式文件副本上复核启动、权限、OpenD历史查询、23只数据、指针切换、EMA/ATR缓存刷新及横竖屏；再受控切换8506。不得从普通页面重绘触发行情请求。
4. 若新版本异常，停止新的更新任务后用 `FutuVersions.rollback()` 将指针原子切回 `previous`，清理页面缓存并核对旧版本完整可用。代码部署回滚须恢复备份的运行文件；用户数据库和人工计划不被历史版本操作修改。
