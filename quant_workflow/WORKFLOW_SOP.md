# 富途量化：半手动策略筛选与前测 SOP

版本：V1.0；规划日期：2026-10-08（Asia/Shanghai）。

目标：以最少必要工程工作，确定哪些策略值得进入模拟盘 forward test。
流程获用户同意；实际进度和阻断项见 [STATUS.md](STATUS.md)。计划不等于已验证结果。

## 1. 工作方式与范围

Codex 写富途量化 Python 代码、检查数据、测试和分析；用户复制代码到牛牛，配置并运行历史回测，提供日志和交易结果。
先用平台回测筛选，再按需使用 OpenD 做模拟盘前测。当前交付先解决环境与数据诊断，不绕过前置验收去生成候选收益。

| 项目 | 初始约定 |
|---|---|
| 标的 | SPY 先跑通，再测试 QQQ；分别记录结果 |
| 时段 | RTH；内部记录 UTC，展示 America/New_York |
| 周期 | 检查 1m、5m；第一轮优先 5m 完整 K 线信号 |
| 风险范围 | 第一轮只做多、不融资、单一持仓；仓位与风险数值在正式实验前登记 |
| 策略家族 | EMA 基线、ORB、First Pullback |
| 搜索预算 | 每家族 3 个预先登记配置，共最多 9 个；一次只改变一个核心参数 |
| 晋级预算 | 每家族最多一个冻结样本外候选；优先 1–2 个进入模拟前测 |
| 数据因素 | 先价格类；VWAP、量比等依赖成交量验证，不能仅因接口有值就使用 |
| 本轮不做 | 自动化控制面板、Webhook、期权研究、真实账户、真实订单 |

后续具体进出场规则、参数值、研究日期、资金、单笔风险、最大回撤上限仍须在运行前冻结；未设置不是零，也不能默认已批准。
回测订单仅在用户明确选择的历史回测环境产生。模拟盘下单、部署、合并、删除分支和真实交易分别授权。

## 2. 阶段与成功标准

| 阶段 | 操作 | 可核查产物 | 晋级条件 |
|---|---|---|---|
| 0 环境确认 | 记录客户端版本、Python 编辑器、数据权限、触发选项、日志保存与结果导出能力 | 能力清单 | 当前可用/未知/不可用明确区分 |
| 1 数据诊断 | 无下单平台探针；按需执行 OpenD 有界历史抽查，再扩展研究区间检查 | 原始样本、哈希、质量报告、异常清单 | 所需数据字段、区间和口径通过；抽查不能替代全区间 |
| 2 执行验证 | 使用 EMA 基线验证下一根成交、去重、仓位、退出与成本 | 逐笔核对及重复运行结果 | 信号与成交对应，净盈亏可复算 |
| 3 小规模筛选 | 三家族各最多三个配置，统一风险与成本口径 | 包含失败实验的完整登记表 | 验证区间选出每家族最多一个版本 |
| 4 冻结样本外 | 冻结代码、参数和判定线后使用保留区间 | 样本外及压力测试报告 | 准入表通过；不足则证据不足或淘汰 |
| 5 模拟前测 | 移植冻结规则，核对平台与 OpenD 信号，再启用已授权模拟执行 | 信号、模拟成交、日结和累计报告 | 按预登记观察周期复核，不宣称自动盈利 |

只有数据合格才能判断策略表现。工程测试 PASS、OpenD 连接成功、平台能运行，均不能替代数据资格或策略证据。

## 3. 数据检测 SOP

### 3.1 先锁定口径

每份检查报告绑定：来源、接口/客户端版本、标的、字段、周期、日期、时段、时区、时间标签、复权方式、采集时间、文件哈希与检查器版本。

- 富途内置量化回测为动态前复权；OpenD 此次探针明确使用 `AuType.NONE`。
- 不能直接将今天下载的静态前复权数据当成历史某时刻的动态前复权输入。
- 平台数据与 OpenD 分别验证；同属富途不是独立数据源交叉验证。
- 不能把触发时间当成 K 线源时间。无法取得源时间时记录 `NOT_VERIFIED`。

### 3.2 两层检查

1. 平台层：复制 `platform_data_probe.py`，历史回测观察平台实际返回的 1m/5m OHLCV 和 EMA20。
2. OpenD 层：运行 `opend_data_probe.py`，只获取一个已完成交易日的 1m/5m 历史数据，不订阅行情、不访问账户、不下单。
3. 对齐后比较平台样本。若源时间、动态复权、截取范围尚不明确，平台对照保持未验证。
4. 先小样本排查口径，再扫描完整研究区间。应覆盖普通日、夏令时切换前后、半日市、公司行动附近日期。

### 3.3 检查清单

| 项目 | 方法 | 失败或未知时的处理 |
|---|---|---|
| 覆盖 | 按交易日历逐日列出预期、实有、缺失与额外 K 线 | 不用前价填补可成交 K 线；列明排除日期及比例 |
| 日期/时区 | 美东交易日历、夏令时、假日、提前收市 | 不全年使用固定 UTC 偏移 |
| 标签 | 验证原始标签对应 bar-start 还是 bar-end，再统一 UTC bar-start | 无法解释的缺口/边界阻断检查 |
| 唯一性与排序 | 时间戳重复、倒序、缺失 | 不默默排序或删除重复后宣布原始数据通过 |
| OHLC | 有限正数，`low <= open/close <= high` | 失败 |
| 成交量 | 缺失、负值、零值、单位及复权口径 | 负值失败；零值调查；依赖它的策略暂缓 |
| 跨周期 | 完整 1m 汇总成 5m，分别比较 OHLC 和 volume | 差异逐项记录，不能根据观察结果临时放宽容差 |
| 公司行动 | 分红/拆股附近的输入、指标、现金和持仓 | 未对齐前不可将差异解释成策略表现 |
| 指标 | 一致输入下复算 EMA 等，明确初始化与预热窗口 | 预热不足或算法定义不一致保持未知 |
| 前视 | 信号只能读取当时已可用的输入 | 未完成 K 线不得冒充收线数据 |
| 独立核对 | 有合法可用的第二数据源时抽查价格与事件 | 没有时明确准确性验证的局限 |

正常完整 RTH 日通常为 390 根 1m / 78 根 5m，半日市由日历决定。
当前 OpenD 探针价格绝对容差固定为 `1e-8`（不复权同源价格），成交量差异容差为 0。
它只检测结构、当日覆盖、时间标签和跨周期一致性；不验证全历史、复权、指标、实时权限或成交。

### 3.4 状态定义

- `SAMPLE_CHECKS_PASS`：仅指定样本和已实现检查通过，不代表整个数据源或策略合格。
- `FAILED_DATA`：有明确结构/覆盖/一致性错误；保留证据，停止依赖该问题的绩效结论。
- `NOT_VERIFIED`：必要证据缺失，不能以零、默认值或本地测试替代。
- `BLOCKED`：连接、接口、依赖等执行条件失败；不是策略亏损。

数据问题按字段依赖传播。价格检查通过但成交量不一致时，量价策略仍阻断；价格策略也须完成自己的全区间和平台输入验证。
排除异常区间的规则必须在查看策略收益前确定，必要时重新预热，不能挑选性删除亏损日。

## 4. 回测执行验收

逐笔检查首笔、末笔、每种退出原因以及全部异常；保存信号时间、订单时间、成交时间、价格、数量、费用。

- 每 K 线触发是在新 K 线开始；`select=2` 表示倒数第二根，但具体配置下的完成状态仍需实测。
- 首次开盘触发读取的上一根可能属于前一交易日；不能当成当日最新完成 K 线。
- 不假设平台下单即成交，不把订单提交价当成交价，不重复建仓。
- 默认完整 K 线信号之后下单，核实实际撮合是否符合下一根成交规则。
- 收盘退出考虑提前收市；最后一根不一定存在下一次 RTH 触发。
- 回测 Tick 是 1m 生成的四点路径。止盈止损同分钟双触发须保守复核，不能利用固定模拟路径获取优势。
- 费用记录实际平台规则；滑点不能配置时另做明确标注的成本分析，不能冒充重新撮合限价单结果。
- 使用 Python 根据真实回测明细复算净盈亏、回撤、费用；相关计算必须有测试。
- 同设置重复运行，解释结果差异。只有收益截图不算完成执行验收。

## 5. 最快筛选方案

### 5.1 规则与预算

每个策略一张规则卡：假设、入场、退出、风险、时段、依赖数据、三个配置、失效条件。
EMA 先验证框架；ORB 只变区间长度；First Pullback 只变机械定义下的回调深度。具体值尚未登记，不能自动凭收益反选。
VWAP 作为后续候选，不挤入本轮九个配置；需成交量资格。

### 5.2 时间划分

初步按时间顺序 60% 开发、20% 验证、20% 最终样本外。覆盖检查后冻结具体日期和边界。
相同研究窗口比较各策略，记录预热区间；边界持仓/标签不能把后续结果泄漏到前一阶段。
验证区间每家族挑一个版本，候选优先顺序在看最终样本外之前登记。
样本外只执行预登记准入判定；修改版本后该区间视为已使用，不能重新宣称未见数据。

### 5.3 准入条件

| 项目 | 第一轮约定 |
|---|---|
| 数据/执行 | 所需范围检查通过，无前视、无法解释的成交和仓位 |
| 净表现 | 样本外扣费、合理滑点后的每笔净期望 > 0 |
| 盈利余量 | 初筛净 PF >= 1.2；无亏损导致 PF 无穷大不能自动晋级 |
| 成本压力 | 手续费保持真实，滑点加倍后净期望仍 > 0；无法复核成交的列为未知 |
| 回撤 | <= 事先登记的 D_max；D_max 未填写时不得判 PASS |
| 稳定性 | 验证区间相邻参数没有明显崩溃，分月/阶段表现与逻辑一致 |
| 样本量 | 约 100 笔样本外、至少 3 个月作为检查起点；不是充分证据或统计保证 |
| 基准 | 报告 Buy and Hold，同时说明持仓时间、隔夜风险和仓位差异 |

净 PF = 盈利交易净利润合计 / 亏损交易净亏损绝对值合计；费用按真实交易分配。
集中于少数大盈利可能符合趋势策略，须分析集中度而非机械删除最大盈利。
所有阈值是筛选约定，不是盈利保证；相邻参数稳定不能单独证明没有过拟合。

结论仅四类：进入候选前测、仅观察收集证据、淘汰、数据/执行阻断。
候选合格后优先规则可复现、成本余量足、风险可接受、实现简单者。
高度相似策略先留简单者；全部不合格则没有候选，不能强行选冠军。

## 6. 单次实验 SOP

1. 登记编号、版本/哈希、全部参数、数据资格、日期、成本、风险及目标。
2. 核对范围变化；新增日期/字段需要补检。
3. 短区间验收行为，不依据利润调整准入门槛。
4. 执行预登记回测，保存包括失败实验在内的全部记录。
5. 保存代码、设置、日志、成交、报告；截图仅补充。导出不可用时记录限制。
6. Python 复算及核对，比较净期望、PF、回撤、分月表现、交易数、持仓时间和基准。
7. 填写准入表与决定；不覆盖旧版本，不隐藏失败尝试。
8. 冻结晋级版本。人工选择修改时登记新研究，不直接改正在前测的版本。

前测每天输出日结与累计证据，包括无交易日、断线、拒单及异常。
信号观察与券商模拟成交分别标注；先核对两环境信号，再评价收益。
每天最多三个优化选项，包含保持冻结/继续收集，由用户选择。
工程安全故障可立即停止新入场，统计评价按预登记观察窗口进行，不因一两天亏损自动调参。

## 7. 文件与权限

项目改动使用独立 `codex/` 分支及 Draft PR；测试后提交，不自动合并。
本地 `artifacts/` 保存历史样本与检查结果并忽略提交；公开仓库只放代码、流程及不含账户信息的摘要。
不上传账户、密钥、客户端私人日志；不修改原工作区的旧项目与未跟踪交易脚本。
外部能力未取得时标记未验证，不以模拟单元测试声称平台已经联通。
