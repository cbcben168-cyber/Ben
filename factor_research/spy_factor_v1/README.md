# SPY_FACTOR_RESEARCH_V1 使用说明

## 研究目标与边界

本版本只研究一个条件：

```text
Close(select=2) > EMA20(select=2)
```

它比较信号完成 K 线的收盘价与 20 周期 EMA，并观察之后 3、6、12 根已完成 5 分钟 K 线的收盘价变化。它是条件收益研究，不是交易策略；信号价与未来价都不能直接解释为可成交价格，也不计算交易 PnL。

第一轮代码固定为 2026/09/28–2026/10/06 的功能验证。该区间的结果禁止认定为有效 Edge。代码不使用 Volume，不调用账户、持仓或订单接口。

## 富途量化中如何运行

1. 在富途量化中新建 Python 历史回测策略。
2. 打开 `SPY_FACTOR_RESEARCH_V1.py`，复制整个文件；不要添加顶部 `import` 或说明字符串。
3. 在富途编辑器中全选旧内容并完整粘贴，然后保存。
4. 在回测向导中把唯一驱动资产设置为 `US.SPY`。
5. 使用美股正常交易时段（RTH）与行情驱动循环；不要选择每天只运行一次。
6. 首次回测日期设置为 `2026/09/28` 至 `2026/10/06`。
7. 启动历史回测，保留所有以 `FUTU_FACTOR_V1|` 开头的日志。
8. 手动将完整 `RunLog_*.csv` 导出到 Windows Downloads；本地进度看板会在运行期间自动识别并导入。

日志正文采用 `FUTU_FACTOR_V1|{JSON}` 契约。看板不会根据文件名猜测因子或跑次，也不会接受旧数据探针作为正式因子结果。

不要修改原 Gate5B 探针。本文件是独立研究程序。

## 正常输出与验收

日志记录类型：

| `event_type` | 含义 |
|---|---|
| `RUN_START` | 固定版本、日期、观察范围、代码 hash 和禁止事项 |
| `SIGNAL` | 一个 09:35–14:55 ET 的有效因子事件 |
| `LABEL_MATURED` | 到期后才计算的 3/6/12 根未来收益 |
| `DAY_STATUS` | 每日完整性检查 |
| `SUMMARY` | DAY 或 CUMULATIVE 的分组统计 |
| `ERROR` | 缺失、错过观察时刻、跨日残留或接口错误 |
| `RUN_END` | 最后一日完成后的全跑次完整性尾标记 |

一个完整正常交易日应有 65 条 `EVENT`，每个周期各 65 条 `OUTCOME`。本次 7 个完整交易日理论上应得到：

- 455 条 `EVENT`；
- 3、6、12 根周期分别各 455 条 `OUTCOME`；
- 每日最后一条 `DAY_STATUS` 为 `COMPLETE`；
- `PASS.n + FAIL.n = ALL.n`；
- 没有 `ERROR`。

只要数量不符、出现 `ERROR`、某日为 `INCOMPLETE`，就先诊断平台触发和数据，不进行因子有效性解释。

## 字段与统计口径

核心事件字段：

- `event_id`：交易日与 ET 分钟组成的事件标识。
- `trigger_et` / `trigger_utc`：事件触发时间；UTC 为审计主时间，ET 用于交易时段边界。
- `close` / `ema20`：同一次触发中以 `K_5M, select=2, RTH` 读取的完成 K 线值。
- `factor_state=PASS`：`close > ema20`；否则为 `FAIL`。
- `horizon_bars`：3、6、12，对应 15、30、60 分钟。
- `return`：`future_close / signal_close - 1`。

每个周期报告三组：

- `ALL`：不加因子筛选的全体事件基准；
- `PASS`：条件成立；
- `FAIL`：条件不成立。

统计字段：

- `n`：可在同日完成观察的样本数；
- `mean_return`：算术平均未来收益；
- `median_return`：中位未来收益；
- `win_rate`：`return > 0` 的比例，零收益不算胜；
- `delta_mean_vs_all`：该组平均收益减去同周期 `ALL` 平均收益。

连续 5 分钟事件的 15/30/60 分钟观察窗口大量重叠，因此日志固定包含 `overlap_warning=TRUE` 和 `independent_samples=FALSE`。原始样本量不能被当成独立样本量，不能直接用普通独立同分布假设宣称显著性。

## 回测时间建议

富途官方 Futu API v10.11 文档说明，60 分钟及以下历史 K 线最多提供最近 8 年；但这不是对富途量化编辑器单次回测区间的保证。量化客户端实际可选范围仍取决于版本、行情权限、品种和数据供应情况，必须在回测向导中实测。官方接口说明：<https://openapi.futunn.com/futu-api-doc/en/quote/request-history-kline.html>。

建议按以下顺序推进：

1. **功能验证：7 个交易日**

   当前固定区间，只验证触发、完成 K 线、到期计算、日志与样本守恒。

2. **开发样本：至少 2–3 年**

   覆盖上涨、下跌、横盘、高波动和低波动环境。若平台允许，优先使用更长的 SPY 5 分钟历史。

3. **独立样本外：至少最近 6–12 个月**

   在查看样本外结果前冻结因子定义、时间窗口和统计方法。

4. **稳健性检查**

   按年份、波动环境和日内时段分层；使用按交易日聚类或区块 bootstrap 等能处理重叠窗口的方法。

更长历史通常能降低偶然性，但“时间久”本身不能证明有效。有效性至少要求 PASS 相对 ALL 的差异在多个市场环境中方向稳定、样本外仍保留，并且不是由少数日期或重叠事件重复贡献造成。

## 本地测试与真实平台验证分界

本地测试只验证代码结构、时序和确定性计算。它使用富途接口桩，不能证明：

- 富途编辑器接受全部语法；
- 历史回测实际按每个 5 分钟完成 K 线触发；
- 2026/09/28–2026/10/06 每天都返回完整数据；
- 更长历史区间和行情权限可用；
- 因子存在可交易 Edge。

以上项目必须用富途平台日志逐项确认。
