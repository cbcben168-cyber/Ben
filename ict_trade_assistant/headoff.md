## 01. 为什么做这个项目：目标、用户及成功标准

### 01.1 用户实际使用场景

- 主要看 **美股 / ETF / 期权**；偏重 `SPY`、`QQQ`，扩展 `IWM`、`SOXX` 等高流动性标的。
- 有交易经验，想提高读图、看趋势、识别流动性区以及交易执行纪律；不需要仅仅展示 RSI、MACD 的普通股市大屏。
- 主要 ICT 方法：**Liquidity Pools / 前日或前周高低 / Sweep & Reclaim / MSS / FVG / CE / 多周期结构 / 失效价格 / Opening Range**。
- 偏好 **日 K / 4H / 1H 主体方向，必要时 5m/15m/30m 做开盘或触价定位**；不做毫秒级、高频或抢订单流。
- 使用普通 Windows PC、富途 OpenD、TradingView Pro、Codex App；希望鼠标点击即可操作，不想每天输入命令。
- 希望程序先观察和提醒，**人手保留交易最终决定权**，尤其要防止看见短时浮亏就提前平仓。
- 模型、行情和软件成本尽量低；尽可能使用已有订阅与本地 Python 计算；AI 只在解释、复盘或必要的设计任务中使用。

### 01.2 产品必须回答的五个问题

1. 今天应该重点观察 **哪些标的**，原因是什么？
2. 现价距离 **哪个事前标记的关键区 / 价格** 有多远？
3. 当前 ICT SOP 到了 **哪一步，哪些证据已确认，哪些仍在形成或缺失**？
4. 当价格到达特定点位，**下一步建议动作和失效条件** 是什么？
5. 如果真实交易完成，**原计划与实际操作有何偏离，如何用积累的数据改善系统和交易纪律**？

### 01.3 什么才叫成功

**首个可用版本**不要求盈利曲线、不要求自动选出下一笔赚钱交易，也不要求自动分析期权组合；只要求用户能完成完整低摩擦观察闭环：

`双击打开 → 正确显示美东/香港交易时钟及行情状态 → 查看 SPY/QQQ → 看到明确时间戳的 K 线与 PDH/PDL / 开盘区间 → 收到有证据的关键价位提醒 → SOP 决策卡明确“等待/观察/复核/取消” → 用户能记录决定 → 关闭重启后数据仍在。`

**后续成功**用提醒误报率、行情可信度、用户是否及时看到条件、是否减少无计划入场/提前平仓、成交数据完整性和实际风险执行来衡量；不能把“自动提示很多交易”当作成功。

### 01.4 不属于当前目标

- 不再将寻找历史 `VALIDATED_EDGE` 作为继续开发的先决条件。
- 不搭建自动下单系统；任何订单 API（实盘或模拟）不调用。
- 不开发毫秒级 HFT、盘口抢跑或依赖独立服务器/专线/机构数据的功能。
- 不在初版实现上千只股票同时订阅、完整实时期权多腿交易系统、AI 自主优化交易盈利、跨券商自动同步。
- 不向用户展示未经验证的胜率、概率或“系统证明可以买入”。

## 02. 项目历史：哪些成果要继承，哪些旧方向要终止

此部分是**保留审计历史**，不是要求新项目重新执行。

### 02.1 最初 ICT 量化研究

最初研究项目：`ICT-SPY-2022-LAB`、后续 `ICT-M1`、`ICT-M2`。目标是使用 SPY 历史行情，把 Liquidity Sweep、MSS、FVG、CE 等 ICT 机制量化并检验。原 `V1 / V3` 与相关 C0/C1 规范有冻结、只读边界；旧研究在其自身项目保存各阶段证据。

主要资产和事实：

- SPY 美股 RTH **1 分钟未复权数据**，主要回溯区间 **2020-01-02 至 2026-10-16**。
- 已使用的主要数据：约 **663,570 根 1m K、1,707 交易日**，其中 1,695 正常日、12 提前收盘日；具体引用以旧工程校验账本为准。
- M1 研究了 Sweep/Reclaim、MSS 和 FVG/CE 在短周期的条件表现；未得到可部署的稳定 Edge 结论。
- M2 转到 1H / 4H / 日 K；旧历史研究出现过 1D C1 34 笔、4H C1 49 笔等结果，但样本少、盈利集中、历史挑选及 OOS 不足。
- 原 C1 逻辑：**Sweep 确认后至 CE 第一次真实触价前，如果原 Sweep 止损先被完整分钟价格触及，则取消该 Setup**；有多个事件状态、入场/出场路径和资金重叠规则。
- 官方历史裁决：`C1_HISTORICAL_REPLAY_PASS / C1_HISTORICAL_EDGE_UNVALIDATED / NO_DEPLOYMENT`。这些结论不可改写为“已证明赚钱”。
- 一部分更早历史资料存在跨源 OHLC / 数据完整性问题，旧工程已隔离；新项目不得偷偷引入历史污染数据作为实时价格真相。

### 02.2 TradingView Pine v1 / v1.1 / v1.2 的教训

| 资产 | 用途 / 事实 | 新项目如何处理 |
|---|---|---|
| `ICT_M2_C1_Audited_Historical_Trade_Map_v1.pine` | 固定历史审计交易点图层；indicator，不提供正式 Strategy Tester 成绩 | 只读参考 |
| `ICT_M2_C1_Visual_Strategy_v1.pine` | 动态交易可视化代理；非 Python 分钟引擎 parity | 不直接移植为正式信号真相 |
| `ICT_M2_C1_Visual_Strategy_v1_1_SAFER.pine` | 修订成交后重算、失效监测、标签密度等 | 可参考 UI/显示需求；非已验证可盈利策略 |
| TV 2026-10-27 用户上传成交 CSV | 211 笔完整模拟成交；2020–2026 范围内 52 笔 | 历史对账记录，非新看板 OOS |
| Python C1 4H 同区间 | 49 笔 | 保留旧账本，只读 |
| 粗配对 | 相同入场日期+方向 24；TV-only 28；Python-only 25 | **不是逐 Setup parity** |
| `ICT_M2_C1_v1_2_DIAGNOSTIC.pine` | Codex 报告 SHA256 `40c9b2ce62fcca4d7cc752f82d85e45998b1d337ca90ce6d85161b0125b06926`；为无下单功能 indicator 诊断器 | 静态检查已做，TradingView 在线编译和真实输出未验证；不阻塞新 MVP |

v1.2 Codex 历史诊断报告：`DIAGNOSTIC_COMPLETE / NOT_PARITY / DATA_NOT_VERIFIED`；99 项离线测试 PASS 仅代表对应离线测试，**不是 Pine 在线编译通过，不是行情源一致，更不是 Edge 验证**。

最主要工程教训：

1. 一个 `phase` 槽 vs 多 Setup 排队，会**改变接受哪些交易机会**。
2. 高时间框架的同根先后和限价成交，不能随意用 OHLC 猜测真实先后。
3. TradingView 的图表 Session / ADJ / 4H 分桶 / 时区设置必须明确，不能在数据不一致时假称策略规则一致。
4. 图表上出现标签，不代表 Strategy Tester 执行过相同订单。
5. 未来看板可以可靠提醒**价格到了哪里、确认到哪一步**；但不必把它伪装成自动交易回测引擎。

### 02.3 与原有 Futu RTH/NTP 工程的关系

旧 Futu 多阶段研究曾出现**主机时钟资格不足、NTP 抓包证据不完整及收包/收盘判定问题**。这说明“时间戳来自哪种时钟”和“结构何时真正确认”非常重要。新系统须自带时间与数据健康监控，但**不把旧 RTH Smoke 的独立审计资格作为新 Streamlit 看板启动的门槛**。如果时间或行情无法被信任，则相关行动建议 `DATA_BLOCKED`，历史复盘仍可离线浏览。

### 02.4 冻结与隔离原则

- 冻结历史旧 V1/V3、C0/C1、M1/M2 代码、原始行情 CSV、审计 ZIP、原 MD/JSON、交易账本与 SHA 校验值。
- 新系统**只复制经批准的通用 ICT 定义或读取只读参考数据**；不得在旧工程目录直接开发、清理、覆盖、迁移数据库。
- 旧的 Ross First Pullback、其他量化实验或自动化 Controller 等不属于本新系统的研发主线。
- 历史 `NO_VALIDATED_EDGE` 不表示必须停止人工辅助 ICT；只表示禁止宣称系统已证明正盈利。

## 03. 项目范围与 72 小时 MVP 冻结合同

### 03.1 交付截止和实际市场日

用户于 **2026-10-29** 要求在 **3 天内取得一个能用的基本版本**。建议使用的冲刺窗口：香港时间 **10/29–11/01**。优先赶在 **10/29–10/30 美国实际交易时段**验证行情及关键触价。**10/31–11/01 是周末**，可做录制回放、断线模拟和时区测试，但不能把周末的回放说成真实 RTH 推送验证。美国 **11/02** 才是夏令时结束后的首个正常周一交易日；实时冬令时开盘验证可以在 MVP 交付后追加，不能提前谎称通过。

交付目标是**一个真实可启动、可验证的基本版本**，不是用“程序框架已写好”冒充可用产品。任何限制在交付报告明确写出。

### 03.2 MVP v0.1 MUST（必须）

1. **完整可扩展的看板框架**：首页和导航先做好；尚未开发页面标 `COMING LATER`，不放真实功能假按钮。
2. **Windows GUI 一键启动**：`双击打开看板.bat` 或同等启动器，自动打开 `http://localhost:<port>`；清晰报告启动失败原因，用户不必每日运行命令。
3. **市场状态条**：美东 `America/New_York` 时钟、香港时钟、RTH / PRE / AFTER / NIGHT / CLOSED、交易日及早收盘、OpenD 连接、行情权限、最后报价时间、延迟/缓存标记。
4. **真实行情**：优先 `SPY`、`QQQ`；附 `IWM`、`SOXX` 作为可配置扩展。使用 Futu OpenD **行情只读 API**，能显示实际权限、未授权、断线状态；历史缓存必须标记 `CACHED`。
5. **K 线看图**：清晰的 1D / 4H / 1H RTH 价格及成交量主图；能够标注前一完整 RTH 日高低点 `PDH/PDL`、可获取时的 `PWH/PWL`、当前及事前标记的关注区。
6. **Opening Range**：以纽约正式 RTH 09:30 为基准的 **5/15/30 分钟**价格范围，必须等对应窗口完成后再显示 `CONFIRMED`；早收盘、停市、缺分钟不补造。
7. **基础 ICT SOP 决策卡**：`DATA_BLOCKED → WATCH_ZONE → SWEEP_PENDING/CONFIRMED → WAIT_MSS → WAIT_FVG → ENTRY_REVIEW / INVALIDATED` 等明确状态；初版未完全实现的子规则标记 `NOT_IMPLEMENTED`，不能推测成已确认。
8. **关键位提醒**：现价接近、穿越关注位、确认 Sweep/OR 等可用事件；去重、冷却、时间戳、解释和失效逻辑。MVP 首先要有**看板内可靠可追溯的提醒**，桌面弹窗/推送属于增强。
9. **基础可调整设置**：观察名单、提醒距离（例如 ATR 的可配置倍数）、刷新间隔、图层显示、静默/提醒开关；持久保存且变更留痕。
10. **持久记录**：SQLite 或等价文件，保存设置版本、价格关注水平、事件、用户备注及人工已读/取消状态，重启后不丢失。
11. **数据健康和 Fail-Closed**：断开、超时、时间不可信、权限缺失时，停止生成新的 `ENTRY_REVIEW`，继续展示带缓存标签的历史信息。
12. **交付文档与测试**：README、已完成/待做清单、最小回放样本、自动测试、时区测试、使用说明、PROGRESS.md / progress.json、文件/关键配置校验摘要。

## 05. ICT 策略 SOP：哪些可自动化，哪些必须人工判断

### 05.1 新产品中“SOP”不是“自动交易规则”

SOP 是可审计的**交易观察与条件检查流程**，让计算机量化显而易见的价格结构，把待人工确认的市场背景保留给用户。系统输出**下一项该检查什么**，不是自动下“买/卖”指令。

### 05.2 日常五阶段

1. **盘前**：市场 / 重大事件 / 数据状态、RTH PDH/PDL、周线结构、隔夜与盘前区间；初筛 SPY/QQQ 等候选，生成关注位及多空情景。
2. **盘中观察**：监控是否接近事前流动性区域；一旦扫过，区分 **forming** 与收盘确认的 **Sweep + Reclaim**。
3. **交易前检查**：等待已确认 MSS；检查 FVG/CE、结构方向、失效价、数据质量、风险成本与事件风险；呈现人工 `ENTRY_REVIEW`，不自动下单。
4. **人工持仓观察**：用户自行记录真实持仓或计划；根据原计划在触及失效、目标、结构变化时提供 `REVIEW EXIT`，不未经用户同意移动止损。
5. **收盘复盘**：记录提醒是否准确、用户采取何动作、为何不做、是否提前平仓、是否遵守计划，并保留证据。

### 05.3 建议状态机

```text
DATA_BLOCKED ──(行情与时间恢复)──> MARKET_CONTEXT
MARKET_CONTEXT ──(关键位确认)──> WATCH_ZONE
WATCH_ZONE ──(扫过关键位、尚未收盘确认)──> SWEEP_PENDING
SWEEP_PENDING ──(完成 Sweep/Reclaim 收盘条件)──> SWEEP_CONFIRMED
SWEEP_CONFIRMED ──> WAIT_MSS
WAIT_MSS ──(confirmed pivot + confirmed close)──> MSS_CONFIRMED
MSS_CONFIRMED ──> WAIT_FVG
WAIT_FVG ──(FVG形成/CE可计算)──> FVG_CE_ARMED
FVG_CE_ARMED ──(价格到达 + 风险核查)──> ENTRY_REVIEW
ENTRY_REVIEW ──(用户人工确认已执行)──> PLAN_ACTIVE
任一允许状态 ──(止损失效/规则超期)──> INVALIDATED
任一实时信号状态 ──(行情失效/时间无法验证)──> DATA_BLOCKED
```

MVP 可分阶段实现：至少 **DATA_BLOCKED / WATCH / 触价提醒 / WAIT / INVALIDATED** 必须可信；完整 MSS/FVG 实现若尚未通过逐事件检查，明确显示 `PARTIAL / NOT_VERIFIED`，而不能直接显示 `CONFIRMED`。

### 05.4 核心 ICT 术语与防未来函数

- `PDH/PDL`：**前一个完整常规交易日 RTH** 的高/低；不同于盘前高/低、隔夜高/低。
- `PWH/PWL`：前一个已完整结束的 RTH 交易周高/低。
- `Liquidity Sweep`：价格越过已知流动性位；`Reclaim` 是否成立须按**选择的已完成 K 时间框架**规则确认，不因为当前影线形成就当作最终信号。
- `Pivot`：确认右侧 K 必须真的收盘，`known_at` 不等于 pivot 标注发生的历史时间。
- `MSS`：突破的是事前**已确认 Pivot**；未完成 K 线不得算结构确认。
- `FVG / CE`：FVG 完整形成后才能给出中点 CE；不能事后把尚未形成的未来缺口画成当时可知。
- `Stop / Invalidation`：不等于实际可保证的止损成交价；进入价、止损、期权实际价格必须分开。
- `Opening Range`：09:30 ET 开始累积 5/15/30 分钟，窗口未完成期间只显示 provisional。
- 对于多个同时存在的 Setup，不能简化为一个 `phase` 槽后静默漏掉；MVP 若暂时仅支持一个活跃计划，明确显示限制，保留 `setup_id`，不声称“已扫描所有机会”。

### 05.5 统一建议词汇

`WAIT`（等）、`WATCH`（观察）、`REVIEW ENTRY`（交易前人工复核）、`REVIEW EXIT`（持仓/离场人工复核）、`CANCEL SETUP`（该计划失效）、`DATA BLOCKED`（行情不能支持新建议）。

**禁止**根据尚未完成的 K 线直接发出“买入/沽空”确定命令；不展示百分比成功率，除非未来有明确统计定义、足够样本与来源。

## 06. 交易所新时段、DST 与 Opening Range：不能犯错的时间规则

### 06.1 经官方资料核实的截至 2026-10-29 事实

1. 美国股票主流交易所的**常规 RTH 仍为纽约当地时间 09:30–16:00**，并没有因为延长交易时段而取消 09:30 开盘。NYSE、Nasdaq 官方资料仍保留常规开盘/收盘及 Opening/Closing Cross。
2. 美股已有盘前、盘后及券商/其他交易场所提供的部分隔夜交易。**标的是否可隔夜交易、行情是否实时、价格源覆盖哪些交易场所，不能仅凭时间推断**。
3. **Nasdaq 官方公告计划于 2026-12-06 21:00 ET 启动 21:00–04:00 ET 新夜间时段**，构成 23/5，期间 20:00–21:00 ET 暂停。该日程在本交接日尚属未来的实施安排；是否按期上线、券商/Futu 数据是否支持，需要实施前再核实。
4. 美国 2026 年夏令时结束日为 **11 月 1 日**；**2026-10-29/30 的 09:30 ET 对应香港 21:30**，**2026-11-02 起对应香港 22:30**。时区必须使用 IANA `America/New_York`，不可写死 UTC−4、UTC−5 或固定香港 21:30。
5. 美股还存在节假日和提前收盘，例如 2026-11-27、2026-12-24；以交易所日历动态处理，不能用“周一到周五 390 分钟”盲目填满。

官方来源：

- NYSE 常规时段/交易信息：https://www.nyse.com/trade/trading-information
- NYSE 2026–2028 交易日历：https://www.nyse.com/trade/hours-calendars
- Nasdaq 23/5 官方说明（2026-10-23）：https://www.nasdaq.com/newsroom/nasdaq-explains-what-is-23-5-trading
- Nasdaq Trader 2026-08-17 生效通知：https://www.nasdaqtrader.com/TraderNews.aspx?id=ETA2026-46
- NIST 2026 DST 规则：https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst

### 06.2 Session 分层——必须从数据库就分开

| Session | 定义 / 初步观察重点 | 是否可混进 RTH PDH/PDL |
|---|---|---|
| `RTH` | 09:30–16:00 ET（个别提前收盘日例外）；正式 ICT 结构主基准 | **只用 RTH** |
| `PRE` | 常见 04:00–09:30 ET，具体可用性依交易所/券商 | **不能** |
| `AFTER` | 常见 16:00–20:00 ET，依品种与券商 | **不能** |
| `NIGHT/OVERNIGHT` | 旧券商夜盘或未来交易所 21:00–04:00 ET，须标数据来源和实施状态 | **不能** |
| `ALL` | 24h 聚合视图，跨时段混合 | **不能假作 RTH** |

特别注意：Futu 官方 `Session` 枚举有 `RTH / ETH / ALL / OVERNIGHT`；历史 K 接口可能只接受 `RTH / ETH / ALL` 等，并对盘前/盘后/夜盘只支持 **60 分钟及以下周期**。不得将 `ALL` 的 4H 原生请求当作已有可靠保证，也不得把 `ETH` 错写为纯盘前盘后（官方 ETH 可能包含 RTH）。

Futu 官方文档：
- https://openapi.futunn.com/futu-api-doc/en/quote/quote.html
- https://openapi.futunn.com/futu-api-doc/quote/request-history-kline.html

### 06.3 4H / 1H RTH 必须有正确分桶

常规 390 分钟 RTH 会话按纽约 09:30 起算：

- **1H**：6 根完整 60 分钟 + 1 根最后 30 分钟。
- **4H**：首根 240 分钟 + 次根剩余 150 分钟。
- 早收盘按实际缩短会话；不虚构剩余时间的价格/量。
- 若 Futu 原生 4H 分桶与自己用 1m 聚合不一致，图表上要表明来源，选一个受审计口径；不能偷偷混算。
- K 线应记录 `bar_start_utc / bar_end_utc / is_final / session / timezone / source / adjustment`。

### 06.4 开盘策略现阶段怎么处理

用户特别要求分析交易时间变化是否使开盘波动逻辑失效。产品层面的**当前裁决**：

| 逻辑 | 新系统状态 | 处理理由 |
|---|---|---|
| 09:30 RTH 开盘/Opening Range 5/15/30m | **保留为观察工具** | 09:30 仍是真实常规开盘及价格发现事件；无证据表明已失效 |
| 前日/前周 RTH 高低 Sweep | **保留** | 明确基于已完成 RTH，不混夜盘 |
| Sweep → MSS → FVG / CE | **核心保留** | 作为 SOP 结构观察，而非已证实盈利的机械策略 |
| 开盘 30 秒暴涨反转 / 早盘追动量 | **暂停自动入场用途** | 点差、盘口/滑点、夜间价格发现可能变化；只能提示风险 |
| 盘前/隔夜高低与跳空 | **单独辅助图层** | 不得当作 RTH 开盘或 PDH |
| 00:00 Midnight Open / ICT Power 3 | **参考线，不做自动入场** | 数据源、Session 连续性、交易日归属需重新定义 |
| Nasdaq 21:00 夜盘“新开盘策略” | **未启用/待验证** | 12/06 新时段在交接日尚未来临，数据权限未知 |

**这是平台与交易时钟的安全设计判断，不是任何策略 Edge 的统计结论**。不要使用“夜盘出现＝09:30 ORB 已被证明无效”或“开盘依然存在＝开盘突破必然盈利”的跳跃推断。

### 07.3 数据品质契约

所有行情、K、事件须附至少以下字段：

```text
symbol, market, session, adjustment, source,
market_ts_utc, received_ts_utc, known_at_utc,
quote_mode [LIVE | DELAYED | CACHED | UNKNOWN],
permission, is_final_bar, age_seconds,
bar_start_utc, bar_end_utc [if K-line],
strategy_id, strategy_version, setup_id [if signal],
state, event_type, evidence, invalidation_price,
config_version, human_action, audit_id
```

*具体字段按事件类别可空，但不能用 0 代替真正未知。*

- 实时报价 / delayed / cached / unknown 显示必须分明。
- 价格超过允许新鲜度、权限未知、OpenD 不通、主机时钟不可信 → `DATA_BLOCKED`，禁止新的可执行条件建议。
- 不同 Session、复权口径、数据源不允许无记录混合；需要派生汇总则显示计算方法。
- `market_ts`（交易所标记）、`received_ts`（程序收到）、`known_at`（用户当时能知道）必须分开。
- 用本地持久事件日志而不是仅在屏幕浮现后消失的标签。
- 每一类提示至少显示“为何触发、关键价格、对应时间、确认级别、什么会否定”。

### 07.4 Futu 权限和额度必须通过探针，不得猜测

- 既有 OpenD 常用地址 `127.0.0.1:11111`（用户原配置）；**实际本机监听状态待检查**。
- 首版只初始化 `OpenQuoteContext`；不创建 `OpenSecTradeContext` / `OpenTradeContext`，不调用解锁或交易订单 API。
- 查 US 实时权限、BMP/Level1/Level2、订阅额度、历史 K 额度、可用 K 周期、报价时间戳及连接错误。
- BMP 或仅快照权限时，不能宣称拥有可推送的 US 实时行情；按接口真实能力降级。
- 实时行情优先少量标的订阅，扫描股票池采用低频批量方式，不做 HFT。
- 优先复用已获得的历史行情缓存，避免不断消耗富途 7 天历史 K 额度；检测缓存日期、Session 和复权口径。

### 07.5 推荐非高频更新节奏（设计值，不是事实承诺）

| 模块 | 初始建议 | 注意 |
|---|---|---|
| 行情输入 | OpenD 推送/受允许的查询 | 受当前账号权限和订阅额度约束 |
| UI 价格卡 | 约 5–15 秒局部刷新 | 不是保证交易所数据实时 |

| 结构确认 | 每根目标 K **收盘后** | 未收盘只显示 forming |
| 价格关键位提醒 | 受事件推送触发、去重冷却 | 不大量刷屏 |
| 经济日历 | MVP 可人工记录或 UNKNOWN | 不得伪造来源和及时性 |

### 07.6 安全、隐私和执行边界

- **从代码及权限结构上不具有下单能力**；不能仅在 UI 隐藏交易按钮但后台仍加载可交易凭据。
- 不调用模拟交易 API；无自动下单、改单、撤单、解锁账户、读取账户余额/持仓，除非未来用户另行明确批准一个隔离的只读交易数据模块。
- 本地数据库及 CSV 默认只存本机，账号、交易 CSV、密钥及敏感日志不提交到公开仓库或云端。
- GUI 启动默认 localhost，不自动开放公网端口。无可靠权限时不可自作主张买付费行情。
- 看板和 TradingView 只是辅助；**实际交易由用户在券商终端独立操作**。

## 08. 参数调整：解决太严没有机会、太松提醒过多的问题

### 08.1 从第一天预留 Strategy Lab

用户要求以后能在看板直接微调策略基础参数，因阈值过严可能整天无 Setup，阈值过松可能一屏伪信号。设计需区分：

**A. 低风险观察参数（可在 UI 动态调整）**
- 观察股票池、排序、提醒距离（例如 ATR 倍数或百分比）、音量、冷却期、主图图层、显示周期、行情 UI 刷新。
- 更改有时间戳，并明确影响“提醒密度”，不自动改变历史策略定义。

**B. ICT 核心逻辑参数（只能创建新版本后生效）**
- Pivot 左右确认根数、Sweep/Reclaim 定义、MSS 等待根数、FVG 搜索窗口、CE 触价要求、ATR 周期/缓冲、有效期、失效条件、RTH/ETH 输入口径。
- 旧 C1 冻结参考：strict pivot L/R=2；Sweep→MSS 最长 3 根 HTF；MSS 后 FVG 窗口（4H=4、日K=5；以冻结规范为准）；CE 50%；Sweep stop buffer 0.1 ATR14；2R、4H/日K不同最大持仓时间。**这些是历史研究参数，只是新 SOP 候选模板，不能直接当成新系统盈利验证或原样强制复刻。**
- 每个变动形成 `strategy_id + version + effective_at + changed_by + reason + diff`，且不回改旧提醒的判断口径。

**C. 硬安全门禁（不能为了增加机会而宽松调整）**
- 时间可靠性、行情是否真实与新鲜、权限缺失、未完成 K 不可确认、明显错误行情/缺分钟、人工确认不能绕过已发生的事实。

### 08.2 必须有机会漏斗，不靠直觉乱调

示例口径：`扫描总数 → 数据质量合格 → 接近关键价格 → Sweep 候选 → 已确认 Reclaim → MSS 确认 → FVG/CE 等待 → 人工 Review`。显示每阶段候选数、被拒绝原因和相应条件；无机会时先诊断是股票池、市场环境、时间窗口还是规则太紧。提醒太多时优先查重复、非关键水平、冷却期，而不是一味增加指标。

推荐提供 `STRICT / STANDARD / RELAXED / CUSTOM` 观察档，但**这不是具有已证实盈利差别的模型**，仅用于体验、观察/提醒密度；保存版本与生效时间。

### 08.3 不再做盈利回测，如何评价调整效果？

只比较真实运行后的**观察行为**：有效提醒数、重复提醒率、数据缺陷、人工复核结果、关键机会是否及时提示、实际交易执行偏差和用户可接受的工作量。策略参数一经更改，应将前后运行期分开；不得把旧历史价格重新扫描得到的“机会”当成真实时间当下可见的信号。

## 09. 后期成交数据上传、交易归集与纪律优化

**此章为后续路线，非 72 小时承诺。** 用户已明确提出需求：交易结束后可上传富途数据，系统自动收集，后续借此改善策略和交易行为；一笔交易可能**多次开仓、多次部分平仓**，尤其存在多腿期权。

### 09.1 首选方案：CSV 上传，而非首版连接交易账户

- 用户从 Futu 手动导出真实成交 CSV，在看板「成交导入」上传。
- 保留原文件、文件 SHA256、上传时间、原字段、来源和不可变的 `deal_id/order_id`（若实际存在）。
- 导入前进行日期/时区/币种/数量/价格/方向/合约乘数/费用校验，识别重复上传，先显示预览和错误提示。
- 原始成交表（不可改） → 归集候选（可人工调整） → 交易计划关联 → 已实现/未实现盈亏及纪律指标。
- 即使 API 存在 `history_deal_list_query`，它也是交易账户读操作；**只有未来用户明确批准**才可考虑另建受限只读模块，不能自动连接。

Futu 历史成交官方资料：https://openapi.futunn.com/futu-api-doc/en/trade/get-history-order-fill-list.html

### 09.2 需要的数据模型

```text
source_file (file_id, sha256, uploaded_at, source)
raw_fill (deal_id, order_id, account_alias, symbol, contract_id,
          fill_time_utc, side, qty, fill_price, fee, currency,
          option_expiry, strike, put_call, multiplier, source_file_id)
trade_group (trade_id, user_label, strategy_id, strategy_version,
             plan_id, opened_at, closed_at, status)
trade_fill_link (trade_id, deal_id, qty_assigned)
trade_decision (plan_id, planned_entry, invalidation, target,
                planned_risk, manual_reason, actual_action, changed_at)
trade_review (trade_id, actual_pnl, realized_R, execution_deviation,
              early_exit_reason, lessons, completeness)
```

**不能简单按同一天同一股票合并**，也不能把跨日分批成交拆成独立交易。需要 FIFO/指定配对等明确规则及人工纠正入口；对于期权还要考虑 Vertical/Calendar/IC 等多腿、部分平仓、行权/指派、币种、费用、合约乘数。缺真实费率或链路数据，盈亏状态标 `INCOMPLETE`。

### 09.3 后期哪些复盘指标最有价值

- 提醒出现 → 是否被用户看到 → 是否符合 SOP → 是否执行 → 真实结果。
- 用户提前平仓频率、偏离入场价、风险预算超限、因担心利润回吐而提前离场、止损移动次数及理由。
- 交易按策略/市场环境/时间框架/期权结构分组后的**实际**净盈亏、风险标准化 `R`、费用/滑点、交易数及数据完整率。
- 不能拿未成交价格路径当作真实成交，不能以某次回放收益冒充交易日志盈利。

### 09.4 优化闭环

`收集事件与交易 → 数据质量检查 → 定位执行或信号问题 → 提出一项具体改变 → 用户确认 → 保存新版本 → 向后观察 → 周/月复盘`。

例如提醒太多先调整提醒距离；经常提前平仓先改执行 SOP，而非直接缩短目标；亏损集中在某类 Setup 时先确认样本和交易成本，不可根据 2–3 笔交易否定整个结构。

## 10. 后期多策略系统：未来添加 ORP 等，不破坏 ICT 主线

用户明确要求未来可以加入其他策略并比较数据。因此**架构必须模块化，但 MVP 不开发全部插件**。

### 10.1 模块边界

共享：Market Data、Session/DST、Event Bus、Watchlist、Price Chart、Alert、Config、Raw Fill、Review、Risk、UI。  
独立：每一策略的 `detect()`、其核心参数、`strategy_id/version`、事件 schema、适用市场/时段及 SOP。

未来策略：现有 ICT（主线）、开盘区间 ORP/ORB（需定义 Session）、其他经用户明确同意的趋势/期权辅助模块。**添加其他策略必须获得用户明确业务层同意**；不得为了跑出漂亮回测曲线擅自转主线。

### 10.2 横向比较要公平

- 同一时间 / 交易池 / 相同 LIVE/DELAYED 数据质量下比较提醒数量、人工确认、执行纪律、误报和真实收益。
- 股票/期权不可单纯比较净美元利润：同时显示最大预定风险、实际 R、费用、持有时间、样本量及可用性。
- 多策略同一 Setup 只对应一次真实交易，可记录 `source_strategy_ids`，不能重复计算利润。
- “没有交易”的 Setup 只能放在机会/观察统计，不能假装执行并计入交易绩效。
- 新策略的参数版本化，不重新解释旧数据；对未知交易成本、IV、期权报价标记 `UNKNOWN`。

### 12.2 本轮交接推荐用法

- **指令类型**：全新独立项目，非修改 ICT-M2 原项目。
- **推荐模型**：Codex App 能选到的高能力编程模型；前次建议 GPT-6.1 Sol（可选时），否则当前可用 GPT-6；不要凭空保证一定有这些菜单选项。

- **协同方式**：让 Codex 写代码并本机运行测试，用户只需按文档双击看板、确认 US 行情权限、提供必要的错误截图；不要每天要求用户手动组织长命令。

### 12.3 Token 规划，不要误用 Plus 额度概念

此前按 MVP 缩减范围估计 **约 5–12 万 Token**（包含基础开发及有限返工余量）；完整长期平台此前估计约 **46–90 万 Token**，但这些是**粗略工程规划而非实际用量或 Plus 保证额度**。Codex Plus 的消息/任务限制随模型、推理强度、任务大小和产品规则变化，不能把“Token 数”直接除以某个官方固定吞吐量得到准确完成日。

**降低开发成本**：

1. 完整范围一次锁定；由简化数据契约和单页骨架开工，不反复大改 UI 架构。

5. MVP 用 Python 本地规则处理，不需要每条实时行情都发给 AI 分析。
6. 严格 timebox：做完一个可以实际使用的核心模块再继续，不因追求“十全十美”错过三天目标。

## 13. 高风险事项／绝对禁止踩坑清单

> **这章优先级仅次于“用户最新决策”。任何接手模型自认为有更聪明方案，也必须遵守这些边界。**

1. **禁止跑偏回历史 Edge 研究**：不再次把 Pine-Python parity、C1 统计检验、PF 优化设置为看板交付阻断。可引用旧结论解释风险，不复活旧路线。
2. **禁止自动交易**：不能建真实、模拟或试探订单；不能创建 TradeContext、调用下单/撤单/解锁 API，不能建立无人值守下单任务。
3. **禁止覆盖旧工程**：冻结 V1/V3/M1/M2/C0/C1、历史数据与 SHA；新工作独立目录。
4. **禁止高频和昂贵系统**：不要求毫秒级行情、机房托管、收费机构级数据或大规模数据采购。
5. **禁止把行情 Demo 当 LIVE**：本地回放必须显著 `DEMO/REPLAY`；实时权限缺失显示 UNKNOWN/UNAVAILABLE。
6. **禁止把“AI 观点”当可验证的信号事实**：每条建议必须有规则、数值、时间、数据源、失效条件。
7. **禁止盘前/盘后/夜盘与 RTH 混用**：含 ADJ（股息复权）、时区、不同 Bar 分桶差异，必须有元数据。
8. **禁止写死北京时间 / UTC−4**：2026-11-01 EDT→EST，必须使用 America/New_York + 交易所日历。
9. **禁止未来数据泄漏**：未收盘的 MSS/FVG/OR、尚未确认的 Pivot 不能标 `CONFIRMED`。
10. **禁止单槽设置导致静默漏事件**：如 MVP 有 Setup 数量限制，必须明确显示而非暗自跳过。
11. **禁止提前把未来 Nasdaq 21:00 夜盘当现已实现**：2026-12-06 计划要重新检查实际生效和 Futu 接入。
12. **禁止基于陈旧行情继续生成行动提示**：断线、延迟超标或时钟不合格就 DATA_BLOCKED。
13. **禁止调整核心参数后覆盖旧记录**：所有参数变更版本化，有生效时间；旧事件不可重解释成新规则当时有效。
14. **禁止用股票价格代理冒充期权盈亏**：期权链静态资料、Bid/Ask、IV、Theta、Greeks 与实际成交分开，缺失就写缺失。
15. **禁止误合并交易 CSV**：按真实成交 ID、合约及人工计划归集；多次开平、跨日、多腿不按同标的/同日简单归并。
16. **禁止混淆“已展示页面”和“功能完成”**：按钮不能空转，MVP 验收需本机真实运行证据。
17. **禁止过度开发**：三天内先完成主屏及可用功能；复杂策略比较、账务归集、AI 优化排后。
18. **禁止无授权连接个人账户、公开存放成交/账户资料、上传密钥**。
19. **禁止为了增加机会而放宽数据完整性、安全门禁和时钟检查**。
20. **禁止依据一两笔真实交易或一次历史漂亮表现便说“策略已经优化成功”**。
21. **禁止未经批准转换 ICT 主线为 Ross、动量或其他非 ICT 实验**；后期可作为隔离插件由用户批准。
22. **禁止只报“测试全部 PASS”而不区分静态测试、单元测试、TV 在线编译、OpenD 本机接入、实时市场证据**。
