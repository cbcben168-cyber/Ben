## 0. 一页结论：已经决定的事情

| 决策项 | 冻结值 | 备注 |
|---|---|---|
| 主图默认周期 | **1H** | 可选择 **15m / 1H / 4H / 1D**；实际信号严格区分观察与已确认 |
| 候选区 | **Top 5** | 首页显著展示五行，按机会相关性排序；不表示盈利概率 |
| 竖屏方案 | **A — 候选优先** | **市场摘要 → Top 5 → 主图与决策卡 → 当前持仓与事件提醒**；不再提供 B 作为默认布局 |
| 横屏方案 | **三栏主工作台** | 左：市场/候选/持仓；中：1H 图；右：决策卡/提醒 |
| 决策卡字段 | **全部保留** | 当前状态、触发价、候选入场、失效价、RR、建议动作、备注；另附方向、条件证据/SOP |
| 首页持仓 | **必须可见** | 与提醒一起，不能仅藏在二级页面；数据未连接时如实注明 |
| 市场概览 | **SPY / QQQ / IWM / SOXX / VIX** | VIX 是市场波动背景，不直接当作普通股票候选 |
| 技术监控信息 | **降级** | 报价年龄、供应商、权限等移到右上角诊断入口/设置页；异常时仍要有显著安全提示 |
| 双屏目标尺寸 | **2560×1440 横屏 + 1440×2560 竖屏** | 以视口而非仅物理分辨率测试，同时考虑 Windows 缩放 |
| 新系统权限 | **行情只读 / 无下单** | “建议动作”是交易计划审查，不是交易指令或自动执行 |

**主线不可改变**：用最少目光移动完成「谁值得盯 → 接近什么位置 → 价格结构到哪一步 → 该等什么 / 注意什么 → 有无现有持仓冲突」。

## 1. 设计目标与优先级

### 1.1 最核心使用场景

1. 每日打开面板，10 秒内看到市场概览和最值得关注的五个标的。
2. 在候选区选中一只股票，图表和右侧决策卡同步更新；不需要切换多个网页。
3. 在同一个首页同时看见现有持仓/计划与最近重要提醒，避免只看新机会而忽略持仓风险。
4. 重要价格或结构触发时，从决策卡直接看到：**触发价、失效价、下一检查项、风险/回报、为什么建议等待或审查**。
5. 发现报价失效、断连或规则计算不完整时，清楚知道该建议不可靠，但平常不被系统技术数据占据屏幕。

### 1.2 信息分级（不可倒置）

**一级——始终放首页：**
- 市场环境：SPY、QQQ、IWM、SOXX、VIX 的可比较摘要；
- Top 5 候选的方向、ICT 阶段、距下一触发位置、触发价、动作；
- 当前选中标的 1H K 线与关键价格线；
- 决策卡完整字段 + SOP；
- 当前持仓/已建计划及重要风险；
- 最近相关提醒/事件。

**二级——点击展开或另页查看：**
- 详细多周期对照、过去事件、逐项依据、参数详情、策略解释、图层管理；
- 历史提醒、成交上传、人工复盘、统计、未来多策略比较。

**三级——诊断/设置：**
- 供应商报价明细、原始 API、权限等级、报价年龄精确秒数、OpenD 日志、订阅配额和技术错误；
- 正常时只出现一个简洁连接/时效状态标识，**不得继续以 4 张大卡占据首页首屏**。

├──────────────────────────────────────────────────────┤
│ ③ TOP 5 候选雷达（五行全部可见）                     │
│    标的 | 方向/阶段 | 距触发 | 触发价 | 下一动作       │
│    ──────────────────────────────────────────────    │
│    #1 ...                                            │
│    #2 ...        点击一行同步下面所有关联模块        │
│    #3 ...                                            │
│    #4 ...                                            │
│    #5 ...                                            │
├───────────────────────────┬──────────────────────────┤
│ ④ 1H 当前标的主图        │ ⑤ 完整 ICT 决策卡         │
│ PDH/PDL、Sweep、MSS、     │ 状态/方向/触发/入场      │
│ FVG/CE、失效/目标、       │ 失效/RR/建议/备注        │

├───────────────────────────┴──────────────────────────┤

> 这是**信息排列约束**，并非固定像素原样复制。第④⑤区应并排以实现「看图同时看决定」，第⑥⑦区优先并排，宽度不足时才上下排放。

### 2.2 版面预算：以 1440×2560 物理像素、100% 缩放为参考

| 区域 | 高度目标/建议 | 信息密度与呈现 |
|---|---:|---|
| ① 顶栏 | 56–72 px | 只保留名字、纽约/香港时钟、Session、状态灯、设置/刷新 |
| ② 五市场摘要 | 108–140 px | 五个紧凑横向摘要，不用大号供应商报价卡 |
| ③ Top 5 候选 | 390–450 px | 表头 + 五行，不使用内部纵向滚动隐藏第五行 |
| ④⑤ 图表 + 决策卡 | 760–920 px | 建议图表约 54–58% 宽，卡片 42–46%；详情有序分区 |
| ⑥⑦ 持仓 + 提醒 | 400–520 px | 持仓至少一条完整卡片；最新事件 4–6 条 |
| 分隔/导航/余量 | 剩余空间 | 容纳浏览器标题栏、留白、滚动及字体缩放 |

**重要**：这些是设计预算，不是要求写死 CSS `height`。实际可视高度由 Windows 缩放、浏览器窗口边框、缩放率决定；必须先保证阅读性，再减少留白。不能为塞进一屏把字压至 10px 或裁掉持仓/决策内容。

**竖屏优先顺序不可调换**：Top 5 必须在主图区之上；选中标的的图表和决策卡尽量并列；持仓和提醒属于首页，同页可到达，不可藏到“持仓”标签才可见。

### 2.3 不同缩放下的降级规则

- 当实际浏览器 **CSS 视口宽度 ≥ 1120px** 且字段可读时：图表与决策卡并排，持仓与事件并排。
- 当 CSS 宽度低于 1120px、缩放较大或出现内容溢出：Top 5 仍优先完整显示；图表与决策卡改为上下排列，**不能产生水平滚动**。
- 若仍因浏览器缩放导致屏高不足，允许垂直滚动；不能隐藏“失效价”“下一动作”来强求一屏。
- 不假设 1440px 物理屏幕一定提供 1440 CSS px；验收必须覆盖 100%、125%、150% Windows 显示缩放。
- 触控/鼠标点击目标建议 ≥ 36–40 CSS px，正文优先 14–16 CSS px；必要时按系统缩放适配。关键行动和价格不只用红绿颜色区别。

## 3. 横屏：2560×1440（三栏，已冻结）

### 3.1 页面结构

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 顶栏：时钟 Session / 状态灯 / 当前标的 / 设置                       │
├─────────────────────────────────────────────────────────────────────┤
│ SPY       QQQ       IWM       SOXX       VIX  （同一行摘要）        │
├────────────────┬────────────────────────────────┬───────────────────┤
│ 左栏 24%       │ 中栏 49%                       │ 右栏 27%          │
│ Top 5          │ 选中标的 1H 主图              │ 完整决策卡        │
│ 状态/距离/动作 │ PDH/PDL/MSS/FVG/CE/失效       │ 状态/触发/入场    │
│                │ 周期与图层开关                │ 失效/RR/建议/备注│
│ 当前持仓/计划  │                                │ SOP 检查         │
│                │                                │                   │
│                │                                │ 最近提醒与事件    │
└────────────────┴────────────────────────────────┴───────────────────┘
```

### 3.2 尺寸/行为

- 顶栏约 56–72 CSS px；五市场摘要使用一行紧凑条，不设大型卡片区。
- 主工作区三列建议 **左 24% / 中 49% / 右 27%**；允许实测时微调各列不超过 ±3 个百分点，只为消除截断和提高可读性，不改变信息优先级。
- 左栏上方始终 Top 5，下面是当前持仓/计划；右栏上方始终决策卡，下面是事件提醒。
- 中栏图表优先占据可用高度，但图表不得盖住止损、关键水平标签或误导价格轴。
- 容纳最少 5 条候选、完整决策字段、一项持仓/计划和最近 4 条事件。可适度收紧二级说明文字，不得隐藏核心字段。
- 如果浏览器窗口被手动缩窄到不满足三栏，响应式变为两列或一列；不能缩出微小不可读的三栏。

## 4. 各模块字段与交互契约

### 4.1 顶栏（轻量）

**必须：**产品名、当前纽约时间 `America/New_York`、香港时间 `Asia/Hong_Kong`（可切换主显示）、当前市场时段、一个数据质量状态灯、设置/诊断入口、刷新按钮。时间用真实交易所日历和 DST 换算，不能写死北京/香港 21:30 或 22:30。

**不允许：**首页四张大号 `STALE / 上游报价 / 报价年龄 / 美股权限` 卡。诊断面板保留供应商、时间戳、权限、订阅及错误细节，按需打开。

**风险例外：**数据为 `STALE / UNAVAILABLE / INCONSISTENT` 时，顶部有明确异常提示，并在相关决策卡阻止新的“可审查入场”提示。安全信息**不得因为追求美观而隐藏**；正常时才折叠技术详情。

### 4.2 市场摘要（五个，顺序固定）

| 顺序 | 标的 | 默认内容 | 用途 |
|---|---|---|---|
| 1 | SPY | 现价/涨跌、日内方向概况 | 大盘参考 |
| 2 | QQQ | 同上 | 科技与成长倾向 |
| 3 | IWM | 同上 | 小盘广度参考 |
| 4 | SOXX | 同上 | 半导体强弱参考 |
| 5 | VIX | 最新可用指数值/变动 + 是否延迟或不可用 | 风险背景；**不得当成现货股票下单候选** |

- 所有数值必须有数据来源和时间依据，优先把具体诊断显示在展开层。
- 如缺失值，显示 `— / 暂无数据`，不得填演示报价。
- 价格强弱/趋势/震荡标签必须有规则说明；规则不可用则显示 `未判定`。
- 点击 SPY/QQQ/IWM/SOXX 可设为当前观察标的；点击 VIX 打开风险背景详情，不生成股价交易建议。

### 4.3 Top 5 候选雷达（竖屏最高优先）

每行至少呈现：

| 字段 | 说明 |
|---|---|
| 标的 / 方向 | 如 SPY / 潜在多头；`方向未定` 可用 |
| ICT 当前阶段 | WATCH / SWEEP / WAIT MSS / WAIT FVG / WAIT CE / ENTRY REVIEW / INVALIDATED 等 |
| 距离触发价 | **当前价与下一关键价差**，可切换 `$`、`%` 或 `ATR`，并标明单位 |
| 下一关键触发价 | 数字 + 价位类型（PDL、PDH、FVG CE 等）；数据不足时 `—` |
| 下一步动作 | 简短动词句：等待、检查、关注、取消；**不可直接生成买卖订单** |
| 优先级 | 用有据可查的阶段成熟度、触发距离和数据质量排序；不能呈现伪造胜率 |

- 默认显示**五个排序最高的合格候选**。在默认标的池不足五个时，只显示可用数量，并写清“候选不足”，不能填入 VIX 凑数。
- 市场背景固定五个（SPY/QQQ/IWM/SOXX/VIX），**不等于五只都必须进入交易候选池**。候选池默认可包含 SPY/QQQ/IWM/SOXX，未来用户可添加其他有权限标的作为第 5 候选；原样板中的 NVDA 是**演示字段，不是已确认永久自选股**。
- 默认排序：「当前有效且更接近下一触发区域」优先，再参考 ICT 阶段成熟度；明确处理 `INVALIDATED` 和缺数据，禁止其冒充最高优先级。
- 可切换「最近触发 / 阶段优先」，保留手动置顶/固定关注的后续接口；排序变化不改变底层策略信号。
- 点击候选行：同步更新**主图 + 决策卡 + 该标的相关事件**；市场摘要保持全市场对照；持仓面板始终显示账户级持仓，不可因选股而消失。
- 用户已选中标的暂时掉出 Top 5 时，主图不突然跳转；当前选中标的显示“已离开 Top 5”提示，并可一键返回候选。

### 4.4 1H 主图（视觉中心）

**周期：**默认 **1H**，支持 `15m / 1H / 4H / 1D`；所有周期按钮可见。正式信号与价位要标注其来源周期。

**图层优先级：**
1. K 线、可见坐标轴、当前价及数据所处 Session；
2. 前日 RTH 高低（PDH/PDL）和前周高低（PWH/PWL），关键流动性区；
3. 已确认的 Sweep / Reclaim、MSS 结构位置；
4. FVG 区域和 CE（50%）线；
5. 当前 Setup 的触发、失效与候选目标；
6. 可选 Opening Range、盘前/隔夜水平（需明确独立数据源/时段）。

**必须防止：**重复标记淹没 K 线；多根图层遮挡价格；把未收盘的 MSS/FVG 标为已确认；把 ETH 高低混为 RTH PDH/PDL；把缺历史的价位画成已验证。

**交互：**周期切换、图层显示/隐藏、悬停查看价位名称/计算来源/有效时间、点击事件定位 K 线、打开 TradingView 外部图表。图表拖拽/缩放可分批实现，但不可破坏价格轴一致性。

### 4.5 SOP 决策卡（所有用户要求字段都要有）

**信息顺序固定：**
1. 标的、方向和当前 ICT 状态；
2. **下一步动作建议**（最醒目的一句话，诸如 `等待 1H MSS 收盘确认`），附一句理由；
3. **下一触发价 / 触发区间**；
4. **候选入场价 / 区间**（条件未就绪显示“未形成”，而非猜值）；
5. **失效价 / 失效条件**；
6. **R/R 或“待评估”**（说明由哪两个价格和费用计算；止损未定义时不得制造比率）；
7. **备注**（人工可编辑、保存编辑时间）；
8. SOP checklist（流动性水平 → Sweep/Reclaim → MSS 收盘 → FVG/CE → 风险检查）及各项确认时间；
9. 规则版本、最近评估时间、阻断原因（可折叠详情）。

动作只允许助理性质：`WAIT`、`WATCH`、`REVIEW PLAN`、`CANCEL SETUP`、`MANAGE EXISTING POSITION`、`NO NEW ACTION`。任何 `REVIEW PLAN` 均须满足必需信息新鲜、基础条件齐备；最终交易由用户手动做出。

不根据用户打开面板时的某一个报价预先声称“已成交”或“高概率必胜”。用户如果修改参数，必须产生版本记录，既有事件仍保留原版本。

### 4.6 当前持仓/已建计划（首页必须可见）

**最低字段：**标的/策略类型、方向或期权组合标识、计划入场、计划止损/结构失效、候选目标、最大计划风险、当前需要处理的动作、人工备注。真实持仓盈亏只在有可靠成交和合约信息时显示。

- 首版如尚未有授权/导入的真实成交：显示 `未连接交易记录 / 尚无已确认持仓数据`，**不能声称“没有持仓”**。
- 允许人工建立观察计划并标记 `草稿 / 已确认 / 失效 / 已完成`；未接真实成交时不自动标记成交。
- 多笔持仓时显示风险优先的摘要，完整列表在详情面板；高风险持仓必须明显标出，不能被新的 Top 5 切换遮蔽。

### 4.7 事件 / 价格提醒（首页必须可见）

显示最近 **4–6 条**有行动意义的事件，至少有：事件时刻（ET）、标的、事件类型、关键价格/区间、系统当前建议、确认/已读状态。与所选标的有关的事件可高亮，但不得默认隐藏其他标的**高优先级**提醒。

事件类型：接近价位、Sweep/Reclaim 已确认、MSS 收盘确认、FVG/CE 形成/回踩、Setup 失效、重要市场时段事件、现有计划风险变化。优先遵守防重复/冷却规则，不能以刷屏代替有用提醒。

刷新时不抹除事件；提醒可被用户确认/静音，但重要失效和数据不可用信息不能静默消失。

## 5. 双屏同时使用时的规则

- **横屏**负责精细图表与完整交易审查；**竖屏 A**负责扫描及比较 Top 5。两块屏幕可在同一应用开启不同窗口或不同浏览器标签。
- 两屏共用相同的行情事实、事件 ID、规则版本和操作日志，避免一屏显示“已失效”另一屏仍显示“待入场”。
- 默认允许两屏各自独立选择观察标的，防止在竖屏点击候选时突然打断横屏看图；后续可加入**显式**「跟随另一个屏幕」开关。
- 筛选排序、手动备注和提醒确认如支持跨窗同步，应具备冲突处理/更新时间，不得覆盖最新记录。
- 本文件**不要求本阶段就完成跨屏同步功能**；只是预留确定的交互契约，缺失时明确说明为独立窗口模式。

## 6. 数据、时间与提示的不可妥协规则

1. **交易所时间基准**：`America/New_York` 与交易日历；香港时间仅作为显示层；考虑美国 DST 和提前收市。不得写死香港 21:30/22:30。
2. **时段隔离**：RTH、盘前、盘后、夜盘分别保存/标注；默认 1H 与 4H ICT 结构以 RTH 为准，盘外信息只能作为单独观察图层。
3. **价格真实**：现价、图表、关键价位都明确对应可信数据源。无数据则显示空值和原因，**不得用原型演示数字代替**。
4. **闭合 K 线**：任何需要收盘确认的 MSS/FVG/Opening Range，未完成前只能显示 `FORMING`，不能升为 `CONFIRMED`。
5. **技术状态低干扰但不隐瞒**：正常时一个状态灯足够；断线或严重过期时在顶栏和决策卡显示醒目提示，暂停新的入场审查建议。
6. **VIX 限定用途**：仅市场风险上下文；如无有效的 VIX 权限则显示缺失，不用估算值冒充当前指数。
7. **信号可追溯**：每项建议、关键价位及事件保留标的、时间、Session、周期、规则版本、价格来源、确认状态。
8. **非自动交易**：界面不得提供下单按钮或隐式交易行为；期权/价差后续扩展仍需用户明确手工执行。
9. **资料和旧研究保护**：不覆盖 ICT-M1/M2 的冻结资料，也不将 Pine/Python NOT_PARITY 当作开发看板的阻断理由。

## 7. 页面导航及首页外的扩展占位

第一版侧边导航/轻量入口可有：

- **今日工作台**（本文件冻结的首屏，优先开发）；
- **策略参数**（未来支持严格/标准/宽松、版本化参数与机会漏斗）；
- **交易记录**（未来导入 Futu CSV、部分成交与多腿交易人工配对）；
- **策略比较**（未来共享数据口径，ICT 以外策略需用户批准）；
- **期权计划**（未来按真实 Bid/Ask/Greeks 进行风险审查）；
- **设置与诊断**（行情权限、时钟、报价年龄、原始错误与日志）。

未完成的页签标记为 `COMING LATER / 尚未启用`；不以假图或演示持仓冒充生产功能。界面设计冻结**不等于**要求这些功能即刻实施。

## 8. 交互及视觉细则

- 色彩语义一致：正常信息中性、已确认条件克制的正向色、警告/接近区域暖色、失效/数据风险明显的警示色；**不能靠颜色作为唯一证据**。
- 数字等宽、标的和关键价清晰；关键价位与文字标签必须有充分对比度。
- 交易动作文字优先使用简单中文：「等待 MSS」「接近前日低点」「检查 CE 回踩」「Setup 已失效」；必要时旁边标英文缩写。
- 图表标签设定密度上限：同类事件可合并，鼠标悬停时显示细节，切勿重复堆叠标签遮住 K 线。
- 状态必须区分：`WAIT`（条件不足）、`FORMING`（正在形成）、`CONFIRMED`（已确认）、`INVALIDATED`（失效）、`UNKNOWN`（资料不足）。
- 候选切换不清空人工备注，不重置风控设置，不自动调整当前的交易计划。
- 自动刷新不应强制把页面滚回顶部、取消用户排序、清除输入框或打断当前图表操作。
- 持仓和提醒均应包含空状态/加载状态/错误状态；不能因为没有数据就自动消失造成用户误判。
- 当前演示原型支持 A/B 切换，但**正式 V2 需求选择 A**：无需继续向用户询问 A/B；可以保留未启动的 B 原型文件作为历史参考，但不得在正式页面默认切换 B。
